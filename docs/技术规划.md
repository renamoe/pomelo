# 技术规划

## 目标

构建静态前端 Web 3D 物理模拟网站，部署至 GitHub Pages。

## 初步技术选型

| 职责 | 技术 |
| --- | --- |
| 构建 | Vite |
| 开发语言 | TypeScript |
| 渲染 | Three.js |
| 物理模拟 | `@dimforge/rapier3d-compat` |
| 实时调参面板 | lil-gui |

## 架构约束

- 物理与渲染分离，分别管理模拟与画面，通过明确的数据接口同步状态。
- 产物为静态资源，不依赖服务端运行时。

## 当前状态

已搭建 Vite + TypeScript 工程，接入 Three.js、Rapier 与 lil-gui。

## 本地运行与构建

- 使用 Node.js 22.12+ 或 24 LTS，执行 `npm ci` 安装锁定依赖。
- `npm run dev`：启动开发服务。
- `npm run build`：TypeScript 检查并生成 `dist/` 静态资源。
- `npm run preview`：预览构建产物。
- Vite 使用相对资源路径，支持 GitHub Pages 子目录部署。

## GitHub Pages 部署

- 仓库 Pages 设置中的 Source 选择 **GitHub Actions**。
- `.github/workflows/deploy.yml` 在推送至 `main` 或手动触发时运行。
- 使用 Node.js 24，依次执行 `npm ci`、`npm run build`，上传并部署 `dist/`。
- Actions 固定到提交 SHA；部署使用内置 `GITHUB_TOKEN`，无需个人访问令牌。
- 默认访问地址：<https://renamoe.github.io/pomelo/>，以部署输出为准。
- 不提交 `dist/`，无需 `gh-pages` 分支。

## 代码结构

- `src/main.ts`：异步初始化、固定 60 Hz 物理步进、渲染循环和调参面板；热更新时释放资源。
- `src/scene.ts`：共享方块数量、尺寸、地面尺寸与旋转及位姿接口，不依赖物理或渲染库。
- `src/physics/PhysicsWorld.ts`：管理 Rapier 世界、固定地面与100个动态方块，提供步进、位姿读取与越界回收。
- `src/rendering/SceneRenderer.ts`：地面使用普通 Mesh，100个方块共用一个 InstancedMesh；复用变换对象更新实例矩阵，不访问物理世界。
- `src/style.css`：全屏画布及移动端布局。

## 展示与验证

- 沙色地面尺寸为 24 × 1 × 16，水平放置；100个边长0.6的方块分层生成于空中。
- 每次生成或越界重生，在网格槽位上加入随机位置偏移（X ±0.15、Y ±0.5、Z ±0.3），并均匀采样随机旋转；初始槽位间距保证旋转后也不相交。
- 重力为 -9.81，固定60 Hz步进；方块与地面及彼此碰撞，在水平地面上自然落稳。低于 y = -12 时复用原刚体回到空中，重新随机位姿并清零速度与外力，保持总数100；不定时重置已落稳的方块。
- 拖动旋转视角，滚轮缩放，面板切换方块线框。
- 已通过生产构建与浏览器显示检查，并验证随机位置范围、旋转归一化及10秒模拟后的水平地面落稳行为。
- Rapier compat 内嵌 WASM，当前入口产物约 4.92 MB（gzip 约 1.82 MB），构建存在大包提示；未隐藏该提示。
